## Technical decisions

| ID | Date | Decision | Why | Affects |
|---|---|---|---|---|
| D-01 | 2026-10-03 | **Candidate dates.** A procedure's baseline date is its `proposedDate`, else `dentistEarliestDate`. It is movable only with a dentist-supplied window where earliest < latest. Its single alternative date is the earliest permitted date in the next supplied plan year: `max(dentistEarliestDate, nextPlanYear.startDate)`. Within-year shifts and moves to an earlier plan year are not modeled. | The previous fixture used 2027‑01‑10, which no stated rule produced. A deterministic rule makes the optimizer testable. Dollar amounts are unchanged. | Fixture v2 (crown → 2027‑01‑01), engine `compareSchedules`, system design §5 |
| D-02 | 2026-10-03 | **Status vs error.** Incomplete inputs → HTTP 200 `status: "needs_information"` with field paths. Unsupported plan rules → 200 `status: "unsupported"`. Schema-malformed → 400 `BAD_REQUEST`. Well-formed but contradictory (allowed > billed, deductible met > deductible, dependency cycle, overlapping plan years) → 422 `INCONSISTENT_INPUT`. | One unambiguous rule for client and server; incomplete is a normal step in the conversation, not an error. | Contracts `ERROR_HTTP_STATUS`, engine `invalid` result, system design §6 |
| D-03 | 2026-10-03 | **Plan-year keys.** Plan years are keyed by stable IDs (`py-2026`) with explicit start/end dates, never by calendar year. Field paths address procedures by ID: `procedures.crown-1.allowedCents`. | Non-January resets (Q-04); stable paths survive reordering. | Fixture v2, contracts, UI block field paths |
| D-04 | 2026-10-03 | **Build fresh in this repository.** Contracts and engine are new code; the pre-event mobile ZIP and serverless starter are not in this repo. If T0-01 permits reuse, migrate deliberately with the screen map in doc 04. | Avoids relying on unconfirmed reuse permission; keeps an honest commit history. | All phases; revisit after T0-01 |
| D-05 | 2026-10-03 | **Comparison outcomes.** `ScenarioComparison.outcome` is one of `alternatives_found`, `no_lower_cost_alternative`, `no_flexible_timing`, `comparison_incomplete` (a later-date option could not be compared; see `limitations`). | Q-05/Q-11: the UI must distinguish "nothing cheaper" from "could not compare". | Contracts, mobile strategy screen |
| D-07 | 2026-10-03 | **Demo auth first.** *(Superseded for deployed stages by D-10; kept for the local server and tests.)* The API runs `AUTH_MODE=demo`: each device sends a random `x-demo-user-id`, the owner ID is part of every DynamoDB key, the stage is throttled (burst 20, 10 req/s), and records expire after `RETENTION_DAYS` via TTL. `AUTH_MODE=jwt` (authorizer `sub` claim) is implemented and tested but not wired into the template. | T3-03 allows "isolated synthetic-only demo controls"; Cognito setup is cut until the core journey works. Demo mode is **not authentication** and must never hold real patient data. | Backend `shared/auth.ts`, `infra/template.yaml` |
| D-08 | 2026-10-03 | **Three Lambdas.** `health` (no AWS SDK), `cases` (GetItem/PutItem), `calculations` (GetItem only). Pre-bundled with esbuild to `backend/.build/`; SAM packages those folders, so `sam build` is not used. Runtime `nodejs22.x`, arm64. | Least privilege per function without one Lambda per route; reproducible bundles independent of SAM's workspace handling. | `backend/scripts/bundle.mjs`, `infra/template.yaml` |
| D-09 | 2026-10-03 | **Estimates are computed on request, not stored.** Results carry `caseRevision` and `engineVersion`; the engine is deterministic, so the same revision always gives the same result. Case `status` is derived on each write: `ready` when estimable, otherwise `draft`. | Avoids stale stored results in Phase 3. Phase 6 saved strategies will store immutable snapshots. | `CaseService`, estimate/scenario routes |
| D-10 | 2026-10-03 | **Cognito managed login (doc 05, U-03).** Deployed stages use a Cognito user pool with a public mobile client (authorization code + PKCE, no client secret) and an API Gateway JWT authorizer checking issuer and audience; the Lambda owner is the token `sub` (already implemented as `AUTH_MODE=jwt`). Demo test users are created by an admin, with synthetic data only. Login identifies the app user, never their insurance eligibility. | Doc 05 makes working authentication part of the security evidence. Most backend code exists; the work is template resources plus mobile sign-in. | `infra/template.yaml`, mobile auth, T3-03 |
| D-11 | 2026-10-03 | **One Region for every service.** Bedrock model + AgentCore Runtime, Transcribe, Textract, Cognito, S3, SQS, DynamoDB in a single Region. Proposed: `us-east-1`, to be confirmed against the account in T0-04 before the first deploy. | Doc 05 adds Transcribe and Textract; cross-Region calls add latency, IAM and data-handling complexity. | T0-04, all stacks |
| D-12 | 2026-10-03 | **Self-pay comparison semantics (U-01, U-02).** Case gains `coverageMode` (`insured`, `self_pay` or `unknown`); procedures gain an optional `selfPayQuote` (cents, date, source, included scope). Unknown is absent, never 0; an insurer allowed amount is never used as a cash price; a missing quote yields an explicit unavailable branch. The comparison is treatment cost under current coverage, not the value of buying insurance. The $1,200/$725 timing fixture stays primary; the $525/$1,200 example becomes a second fixture. | Keeps one engine and the existing regression intact while adding the coach-requested branch honestly. | Contracts, engine, fixtures |
| D-13 | 2026-10-03 | **Question and UI-block registry (U-01, U-05).** Adopt doc 05 question fields (`questionId`, `fieldPath`, `inputType`, `options`, `allowedResponseModes`, `required`, `reason`, `sourceRefs`, `expectedRevision`). Proposed consolidation, before any mobile code depends on it: one `missing_field` question block with `inputType` (currency, single_select, date, fact_review, attachment) replaces `money_input`/`single_select`/`date_window`/`fact_review`; `source_evidence` replaces `evidence_list`; add `cost_comparison` (insured, self-pay, timing), `coverage_issue` (typed, with blocking severity) and `next_step`; keep `cost_summary`, `benefits_timeline`, `notice`. | One question component with typed inputs is simpler for the adaptive loop and voice/photo answers. No mobile code consumes blocks yet, so renaming now is free. | `packages/contracts/src/ui-blocks.ts` |
| D-14 | 2026-10-03 | **Voice and camera are requested scope (U-06, U-07), with fallbacks.** Press-to-record → private S3 upload via presigned URL → `transcribe_audio` job (Amazon Transcribe batch) → editable transcript → `interpret`. Camera is for photos of documents only, through the same upload/extraction path. Each gets a 45-minute feasibility spike first; a typed/control-only journey stays working throughout. Timing heard in a voice note is `user_reported` and never unlocks the optimizer. | Doc 05 elevates both from stretch. Reusing the case/job/upload contracts avoids a separate voice backend. | Phase 5–6 pipeline, mobile intake |
| D-06 | 2026-10-03 | **Tooling.** npm workspaces, TypeScript 5.9 strict (incl. `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`), Zod 4, Vitest 5. Node ≥ 22.13. Packages compile to `dist/`; tests run against source. | Matches the stack doc; TypeScript 7 deferred to avoid toolchain surprises during the event. | Root `package.json`, `tsconfig.base.json` |
